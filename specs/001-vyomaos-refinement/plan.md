# Implementation Plan: VyomaOS Production Refinement

**Branch**: `001-vyomaos-refinement` | **Date**: 2026-05-24 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `specs/001-vyomaos-refinement/spec.md`

## Summary

Promote VyomaOS from a working prototype to production-grade software by: (1) extracting testable logic from the 2 619-line supervisor monolith into `manifest.rs` and `logging.rs` modules, (2) adding `cargo test` unit tests inside Docker, (3) adding a headless QEMU smoke test via `make test`, (4) enforcing `RUSTFLAGS=-D warnings` as a hard build gate, (5) adding per-app incremental build stamps for all 205 apps, (6) formalising the VYOMA_DRAW protocol in `docs/vyoma-draw-protocol.md`, and (7) adding `make check-manifests` for pre-build manifest validation. All new logic follows TDD (Red → Green → Refactor).

## Implementation Phases

### Phase A — TDD: Manifest Module (extract + test)

**Objective**: Extract manifest structs and pure functions into `supervisor/src/manifest.rs`; write failing tests first.

**TDD sequence**:
1. Write `supervisor/tests/manifest_tests.rs` with failing tests for:
   - Valid manifest parses without error
   - Unknown capability field returns error
   - Missing required field returns error
   - Duplicate app name: second rejected, first retained
   - `watchdog_secs = 0` is valid
2. Move `BootConfig`, `BootEntry`, `AppManifest`, `AppMeta`, `Capabilities`, `WindowRegion` to `manifest.rs`
3. Add `pub fn parse_manifest(path: &Path) -> Result<AppManifest, ManifestError>` 
4. Add `pub fn validate_manifest(m: &AppManifest, registry: &[&str]) -> Result<(), ManifestError>`
5. Run `cargo test` → all tests pass

### Phase B — TDD: Structured Logging

**Objective**: Replace all `eprintln!("vyoma-supervisor: ...")` with structured log macros.

**TDD sequence**:
1. Write `supervisor/tests/logging_tests.rs` with failing tests for:
   - `log_info!(Subsystem::Manifest, Some("hello-world"), "parsed OK")` produces correct format
   - Timestamp is valid ISO 8601
   - Level is one of `INFO /WARN /ERROR`
2. Implement `supervisor/src/logging.rs` with `Subsystem` enum and `log!` family macros
3. Replace all `eprintln!` calls in `main.rs` with `log_info!` / `log_warn!` / `log_error!`
4. Run `cargo test` → all tests pass

### Phase C — TDD: IPC + Lifecycle Tests

**Objective**: Test IPC routing (unknown target, duplicate name) and lifecycle state transitions.

**TDD sequence**:
1. Write `supervisor/tests/ipc_tests.rs`:
   - Route to unknown app → `RouteError` (no panic)
   - Message to self → handled correctly
2. Write `supervisor/tests/lifecycle_tests.rs`:
   - App exits with code 0, restart=never → no restart, log INFO exit
   - App exits with code 1, restart=always → restart attempted, log WARN
3. Extract pure routing logic from `main.rs` into testable free functions
4. Run `cargo test` → all tests pass

### Phase D — Makefile: Warning Gate + Per-App Stamps

**Objective**: Enforce `RUSTFLAGS=-D warnings`; migrate all 205 apps to per-app stamp files.

**Steps**:
1. Add `RUSTFLAGS := -D warnings` near top of Makefile
2. Define `APP_NAMES` list (all 205 app directory names)
3. Replace single `$(APPS_STAMP)` with `define APP_RULE` pattern rule
4. Add `make unit-test`, `make smoke`, `make test`, `make check-manifests` targets
5. Verify `make apps` rebuilds only the touched app after a single-file change

### Phase E — Smoke Test Script

**Objective**: `base/scripts/smoke-test.sh` that boots VyomaOS headlessly and asserts readiness.

**Steps**:
1. Write failing test: script exits non-zero when supervisor does not emit ready signal
2. Add `"all apps spawned"` structured log line to supervisor after all `spawn_app` calls complete
3. Implement `smoke-test.sh` with `timeout 30 qemu-system-x86_64 ... | grep -m1 "all apps spawned"`
4. Add QEMU to Dockerfile if not already present
5. Verify `make smoke` exits 0 on clean build, exits 1 when a manifest is broken

### Phase F — VYOMA_DRAW Protocol Documentation

**Objective**: Publish `docs/vyoma-draw-protocol.md` derived from the contract spec.

**Steps**:
1. Copy `contracts/vyoma-draw-protocol.md` content into `docs/vyoma-draw-protocol.md` (developer-facing)
2. Add a link from `docs/README.md` (or create if absent)
3. Cross-check every command example against `handle_draw_command` in `main.rs`; fix any discrepancy in supervisor code, not documentation

### Phase G — manifest-validator binary

**Objective**: Standalone `make check-manifests` that validates all `apps/*/vyoma.toml` files.

**Steps**:
1. Add `tools/check-manifests/` crate (Rust binary, depends on supervisor's manifest module via path dep)
2. Iterates `apps/*/vyoma.toml`; calls `parse_manifest` + `validate_manifest`; prints structured output
3. Add `make check-manifests` target that runs this binary inside Docker
4. Wire into `make build` as an early gate (runs before `make apps`)
