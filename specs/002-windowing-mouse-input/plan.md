# Implementation Plan: Windowing System and Mouse Input

**Branch**: `002-windowing-mouse-input` | **Date**: 2026-05-24 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/002-windowing-mouse-input/spec.md`

## Summary

Add a supervisor-managed tiled windowing system and software mouse cursor to VyomaOS. The supervisor auto-computes non-overlapping `ceil(sqrt(n))` grid regions for all running display apps, renders a 12×19 cursor sprite composited above all app content, routes mouse move/click events using the `VYOMA_INPUT:mouse:move/click` protocol, and updates keyboard focus on window click with a 2 px inset border indicator.

**Current state**: The supervisor already has partial implementations from earlier phases (P22/P32/P33): evdev mouse reading, Z-order stack, click-to-focus, `fill_rect`/`draw_text` clipping. The missing pieces are: tiled layout engine, cursor sprite rendering, updated mouse event format, and dynamic reflow on spawn/exit.

## Technical Context

**Language/Version**: Rust 1.75 (stable), `x86_64-unknown-linux-musl` (supervisor), `wasm32-wasip2` (apps)

**Primary Dependencies**: `libc` (framebuffer mmap + evdev ioctl), `wasmtime`, `toml`, `serde` — no new crate dependencies

**Storage**: No persistent state; layout is recomputed in memory on every spawn/exit

**Testing**: `cargo test --target x86_64-unknown-linux-musl` via `make unit-test`; smoke boot via `make smoke`

**Target Platform**: Linux x86_64 inside QEMU (virtio-gpu framebuffer, virtio-input mouse)

**Project Type**: OS supervisor (Rust, static musl binary)

**Performance Goals**: Cursor position update ≤50 ms from hardware event; layout reflow ≤500 ms from app spawn/exit; mouse event dispatch ≥30 events/second

**Constraints**: Supervisor binary ≤1 MB stripped; no new Cargo dependencies; single CPU core; no heap allocations in hot paths (cursor draw uses fixed-size arrays)

**Scale/Scope**: 1–9 simultaneously visible display apps; single screen at fixed boot-time resolution

## Phase 2: Implementation Plan

### Task Group A — Tiled Layout Engine (US1, P1)

**A1. Create `supervisor/src/windows.rs`**
- Export: `pub fn compute_tiling(n: usize, sw: u32, sh: u32) -> Vec<(u32, u32, u32, u32)>`
- Algorithm: `cols = ceil(sqrt(n))`, `rows = ceil(n/cols)`, base `cell_w = sw/cols`, `cell_h = sh/rows`
- Last-row expansion: for last row (index `rows-1`), divide remaining width among last-row tiles
- Edge case: `n=0` → return empty vec; `n>9` → clamp to 9
- Add to `supervisor/src/lib.rs`: `pub mod windows;`

**A2. Write unit tests in `supervisor/tests/window_layout_test.rs`**
- `test_1_app_fullscreen`: region equals screen
- `test_2_apps_side_by_side`: two equal halves
- `test_4_apps_2x2`: 4 equal tiles
- `test_3_apps_last_row_expands`: last tile is full-width
- `test_no_overlap_1_to_9`: all n in 1..=9, no regions overlap
- `test_full_coverage_1_to_9`: union covers screen exactly

**A3. Call `compute_tiling` on app spawn**
- In `main.rs`, after spawning a display app: re-collect all display apps, call `compute_tiling`, assign new regions to all `AppState::win_region`
- Update `SpawnedApp::win_region` before `launch_app_threads()`
- Log: `log_info!(Subsystem::Display, …, "layout reflow: {n} display apps")`

**A4. Call `compute_tiling` on app exit**
- In `wait_app()`: after app exits, if it had `win_region = Some(...)`, recompute layout for remaining display apps
- Reflow must complete within 500 ms (timing is well within single-thread scope)
- Trigger border repaint of all windows after reflow

**A5. Remove static window positions from manifest read path**
- In the manifest spawn path, ignore `WindowRegion::x/y/w/h` (these are now supervisor-assigned)
- Keep reading `WindowRegion::width/height` as min-size hints (implement best-effort min-size in `compute_tiling`)

### Task Group B — Mouse Cursor Rendering (US2, P2)

**B1. Add `CursorState` to `supervisor/src/display.rs:Framebuffer`**
```rust
pub struct CursorState {
    pub cx: i32,
    pub cy: i32,
    pub visible: bool,
    saved_under: [u8; 12 * 19 * 4],  // BGRA pixels under cursor
    drawn: bool,
}
```
Add as field to `Framebuffer`. Initialize in `open_fb()` with `cx = width/2, cy = height/2, visible = false, drawn = false`.

**B2. Define cursor sprite constant**
```rust
const CURSOR_W: u32 = 12;
const CURSOR_H: u32 = 19;
// 1-bit mask rows (msb = leftmost pixel)
const CURSOR_MASK: [u16; 19] = [
    0b1000_0000_0000_0000,  // row 0: single pixel tip
    0b1100_0000_0000_0000,  // row 1
    0b1010_0000_0000_0000,  // row 2
    // ... (standard arrow shape)
];
```

**B3. Implement `Framebuffer::draw_cursor()`**
- Save `CURSOR_W × CURSOR_H` pixels from `self.back` into `self.cursor.saved_under`
- Paint cursor sprite (white + 1px black outline) into `self.back`
- Set `self.cursor.drawn = true`

**B4. Implement `Framebuffer::restore_under_cursor()`**
- If `self.cursor.drawn`: copy `saved_under` back into `self.back`; set `drawn = false`

**B5. Integrate cursor into `flush()` pipeline**
- In `Framebuffer::flush()`: call `draw_cursor()` just before `copy_nonoverlapping` (blit to front)
- This ensures cursor is always on top of app content without modifying app's back-buffer state
- After blit: call `restore_under_cursor()` (so back-buffer is clean for next app frame)

**B6. Update cursor position from mouse thread**
- Add `pub fn set_cursor_pos(cx: i32, cy: i32)` to `display.rs` that locks `Mutex<Framebuffer>` and updates `cursor.cx/cy`
- Call from mouse-input thread on every EV_SYN
- Replace hardcoded `const SCREEN_W/SCREEN_H` with `display::screen_size()` for clamp bounds

**B7. Activate cursor on mouse device detected**
- In mouse-input thread: after `open_mouse_device()` succeeds, call a new `display::enable_cursor()` function that sets `cursor.visible = true`
- `draw_cursor()` is a no-op when `visible = false` (headless boot)

### Task Group C — Mouse Event Format Update (US3, P2)

**C1. Update `dispatch_mouse()` event format**
Current: `VYOMA_INPUT:mouse:{lx},{ly},{btn}` (btn is 0=move, 1=click)  
New:
- Move: `VYOMA_INPUT:mouse:move:{lx},{ly}`
- Click: `VYOMA_INPUT:mouse:click:{lx},{ly}:{button_name}`

```rust
// In dispatch_mouse(), replace:
send_reply(&name, &format!("VYOMA_INPUT:mouse:{lx},{ly},{btn}"), inbox);

// With:
if btn > 0 {
    let bname = match btn { 1 => "left", 2 => "right", 4 => "middle", _ => "left" };
    send_reply(&name, &format!("VYOMA_INPUT:mouse:click:{lx},{ly}:{bname}"), inbox);
} else {
    send_reply(&name, &format!("VYOMA_INPUT:mouse:move:{lx},{ly}"), inbox);
}
```

**C2. Handle right/middle buttons in mouse-input thread**
- Current code only tracks `BTN_LEFT (0x110)` → bit 0
- Add: `BTN_RIGHT (0x111)` → bit 1, `BTN_MIDDLE (0x112)` → bit 2
- Pass full button bitmask to `dispatch_mouse()`

**C3. Update mouse-demo test app to use new protocol**
- Create `apps/mouse-demo/` as a display+mouse app that renders received events on screen
- Add to `rootfs.sh` and `boot.toml` (as restart=never, not in default boot)

### Task Group D — Window Border and Focus Indicator (US4, P3)

**D1. Replace title-bar chrome with 2 px inset border**

Current `handle_draw_command()` on `flush`: draws 20px title bar + close button.

New behaviour:
- No title bar, no close button
- Draw 2 px inset border inside the app's `win_region`
- Focused: accent color `0x89B4FAFF` (Catppuccin blue)
- Unfocused: dim color `0x45475AFF` (Catppuccin surface1)
- Border is "inset" — drawn at `(wx, wy, ww, wh)` but content area shrinks by 2px on each side

**D2. Repaint all window borders on focus change**
- After `*focused.lock().unwrap() = Some(name.clone())`, trigger a border repaint pass
- Walk all display apps; redraw their 2 px borders in the back-buffer with correct focus color
- This is done before the next `flush()` call (borders are painted into `back`)

**D3. Auto-focus transfer on app exit**
- In `wait_app()`: if the exiting app was the focused app, call `auto_transfer_focus()`
- `auto_transfer_focus()`: pick the first running display or shell app; set as new focused app; log the transfer

**D4. Remove close-button hit detection**
- `dispatch_mouse()` currently checks for clicks in the chrome region above each window
- Remove the `P32: close-button` check (no chrome → no close button)
- Retain the focus-on-click and Z-order raise behaviour (P33)
