## Changes and environment

- Enable Clap's `env` feature; remove unused CLI monitor import/field and draw-handler parameter.
- Move the existing release settings to the workspace root, where Cargo applies them to both binaries.
- Cast DRM ioctl requests to the target's argument type: musl uses `c_int`, glibc uses `c_ulong`. Preserve the low 32 request bits, including high direction bits.
- Remove the supervisor's forced `musl-gcc` linker. In this builder it injected `/lib/ld-musl-x86_64.so.1` into nominally static PIE executables, which segfaulted before running tests. Rust's default linker produced runnable binaries without a PT_INTERP segment.

## Remaining failures and next work

1. **T0-02 — dependency/build inputs:** most app crates lack checked-in lockfiles. The first `--locked` app build correctly failed; the subsequent build used current per-app resolution, matching the existing Makefile behavior. Generated lockfiles are local only. Pin inputs and check in the intended lockfiles before claiming reproducibility.
2. **T0-05/T0-06 — Python API mismatch:** `test_assertions.py` cannot import `DESKTOP_BG` from `assertions.py`. Seven harness tests expect an older QMP API (`connect`, `move`, `click`, `key`, `wait_log`, `close`). Align the tests with a deliberately specified API, not by deleting coverage.
3. **T0-06 — destructive shared test state:** the harness constructor unlinks shared `/tmp/vyoma-qmp.sock` and `/tmp/vyoma-serial.log`. Harness unit tests run while the session VM is live; this destroys its log and makes the full-suite keyboard test fail. Running VM-only files separately passes that input test. Use per-test paths and safe cleanup; the existing input assertion still does not prove command execution.
4. **T0-04/T0-GATE — guest health:** the VM-only window-content assertion sees a black central region. A separate 15-second capture confirms `clock.wasm` panics at `std::thread::spawn` (`apps/clock/src/main.rs:105`), reports WASI `Unsupported`, exits 134 and loops through restarts. This is an observed guest defect; it is not yet proven to be the sole cause of the black region. The weak smoke/screenshot checks pass despite it. Choose the R1 app set, validate sustained real guest health, and strengthen readiness assertions. Bound restart behavior under T2-07.

No failing test was removed, disabled or marked passing. T0-01 is a compilation/linking fix; these failures remain explicit follow-up work. After merge, reconcile T0-01 and proceed to T0-02, retaining the harness and guest defects as T0 gate blockers.

## Local reproduction

Run from the worktree root with the existing builder available. The helper below matches the final test environment; do not set `CARGO_TARGET_X86_64_UNKNOWN_LINUX_MUSL_LINKER=musl-gcc`.

```bash
vyoma_builder() {
  docker run --rm --user "$(id -u):$(id -g)" \
    --tmpfs /data:rw,mode=1777 --tmpfs /apps:rw,mode=1777 \
    -v "$PWD":/work -w /work vyomaos-builder:latest "$@"
}

vyoma_builder env RUSTFLAGS='-D warnings' cargo test --locked \
  --workspace --target x86_64-unknown-linux-musl --no-fail-fast -- --test-threads=1
vyoma_builder env RUSTFLAGS='-D warnings' cargo build --locked \
  --workspace --target x86_64-unknown-linux-musl --release
vyoma_builder env RUSTFLAGS='-D warnings' cargo check --locked \
  --workspace --target x86_64-unknown-linux-gnu

for app in desktop dock gui-demo shell; do
  vyoma_builder cargo test --manifest-path "apps/$app/Cargo.toml" \
    --target x86_64-unknown-linux-musl -- --test-threads=1
done
for tool in check-manifests gui-test; do
  vyoma_builder cargo test --manifest-path "tools/$tool/Cargo.toml" \
    --target x86_64-unknown-linux-musl
done
vyoma_builder cargo run --manifest-path tools/check-manifests/Cargo.toml \
  --target x86_64-unknown-linux-musl

for manifest in apps/*/Cargo.toml; do
  vyoma_builder cargo build --manifest-path "$manifest" --target wasm32-wasip2 --release
done
# Use a fresh out/ directory: kernel.sh currently skips an existing bzImage.
vyoma_builder bash base/modules/kernel.sh
vyoma_builder bash base/modules/rootfs.sh
vyoma_builder env XDG_CACHE_HOME=/tmp/wasmtime-cache WASMTIME=/work/out/cache/wasmtime \
  bash scripts/test-gui-protocol.sh
bash base/scripts/smoke-test.sh
bash base/scripts/test-e2e-gui.sh

BZIMAGE="$PWD/out/bzImage" INITRAMFS="$PWD/out/initramfs.cpio.gz" \
  PYTHONDONTWRITEBYTECODE=1 /tmp/vyomaos-t0-tests/bin/python -m pytest \
  tests/e2e -v --continue-on-collection-errors
# Separate diagnostic run: avoid unit tests deleting the live VM's serial file.
BZIMAGE="$PWD/out/bzImage" INITRAMFS="$PWD/out/initramfs.cpio.gz" \
  PYTHONDONTWRITEBYTECODE=1 /tmp/vyomaos-t0-tests/bin/python -m pytest \
  tests/e2e/test_boot.py tests/e2e/test_input.py tests/e2e/test_window.py -v
```

The actual run captured each command's output and exit status separately, continued independent checks after failures, and installed `tests/e2e/requirements.txt` into the temporary Python environment. It reused downloaded kernel/BusyBox/Wasmtime archives, not old compiled artifacts. Rootfs assembly verified the BusyBox/Wasmtime hashes; kernel-source authentication remains T0-02. For protocol tests, the same verified Wasmtime archive was extracted into the validation directory; the reproduction command uses rootfs's identical cached executable.
